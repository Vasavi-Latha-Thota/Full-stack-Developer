Inheritance:
It is a process of inherits or aquires the properties and methods from one class to another class
Single inheritance:
If the single child class aquires properties and methods from single parent class is known as single inheritance
Muliple inheritance:
If the child class aquires properties and methods from more than one parent class is known as Muliple inheritance.
Multi level inheritance:
It is a chain of inheritance.
Each class aquires properties and methods from its parent class , child class access  all methods from parent and grandparent classes.
Hierarchical inheritance:
If more than one child aquires properties and methods from one parent class is known as Hierarchical inheritance
Hybrid inheritance:
“If you implement the combination of two or more types of inheritance, it is known as hybrid inheritance.”

Multiple inheritance means a child class inherits from more than one parent class.

class Father:
    def skill1(self):
        print("Father: Cooking")

    def skill2(self):
        print("Mother: Dancing")

Python searches methods in left-to-right order in the inheritance list.
Once it finds the method, it stops searching further.

Advantages of Inheritance
Code Reusability
 You don't need to write the same code again. You can reuse code from the parent class.
Improved Code Organization
 Related features can be grouped logically using parent-child relationships.
Easy Maintenance
 If a bug or change happens in the parent class, all child classes get updated automatically.
Supports Real-World Mapping
 Inheritance models real-world "is-a" relationships. (Example: Dog is an Animal)
Extensibility
 You can extend the functionality of existing classes without modifying them.
Less Code, More Features
 Inheritance reduces code duplication and allows you to add extra features in child classes.
Applications of Inheritance
Object-Oriented Programming
Used to create modular, reusable, and scalable systems.
GUI Applications
E.g., Button, Window, Label classes inherit from a base Widget class.
Game Development
Player, Enemy, NPC → all inherit from Character class.
E-commerce Systems
Product, ElectronicsProduct, ClothingProduct → all inherit from Product class.
Banking Applications
Account → SavingsAccount, CurrentAccount
Educational Apps
User → Student, Teacher, Admin
Web Frameworks
Django, Flask, etc., use inheritance to define views, forms, models.

Disadvantages:
1. Tight Coupling
 Meaning: The child class is dependent on the parent class.
 Simple Example:
If the parent class method name changes, the child class might stop working.
class A:
    def show(self):
        print("Hello")

class B(A):
    def display(self):
        self.show()  # using parent method

# If we rename `show()` in A to `show_message()`, class B breaks.
 Problem:
Even a small change in the parent affects all the child classes.

 2. Can Be Confusing with Multiple Inheritance
 Meaning: When a child class inherits from multiple parents, Python may get confused about which method to run if both parents have the same method name.
 Simple Example:
class A:
    def greet(self):
        print("Hello from A")

class B:
    def greet(self):
        print("Hello from B")

class C(A, B):
    pass

obj = C()
obj.greet()  # Which greet? A or B?
 Problem:
You may not predict easily which method will run. Python follows MRO (Method Resolution Order), but it can be tricky for beginners.

 3. Slower Performance
 Meaning: Inheritance may be slightly slower because Python checks the entire inheritance chain to find a method (especially in multiple levels).
 Example:
If class D → C → B → A, and you're calling a method from A using D's object, Python checks all classes in the chain.
class A:
    def msg(self):
        print("Hi")

class B(A): pass
class C(B): pass
class D(C): pass

d = D()
d.msg()  # Python checks D → C → B → A

 4. Less Flexibility
 Meaning: If the parent class is not designed properly, child classes may face problems or cannot be customized easily.
 Example:
If a parent method does something you don’t need, and you can't easily override or skip it — you're stuck with it.

 5. Overuse Leads to Complexity
 Meaning: If you use inheritance too much or unnecessarily, your code becomes hard to read and debug.
 Example:
If class A → B → C → D → E and you're trying to fix a bug in E, you'll waste time checking A, B, C, and D.

 Simple Tip for Students:
Use inheritance only when it truly makes sense.
Use it to model "is-a" relationships, like:
Dog is an Animal
Teacher is a Person
Avoid using inheritance just to reuse code — that’s what composition (using objects inside a class) is for.

What is a Docstring in Python?
A docstring (documentation string) is used to describe what a function, class, or module does.
It is like a special comment that:
Helps developers understand the purpose.
Can be accessed at runtime using .__doc__.
What is a docstring in Python?
A docstring (documentation string) is a special type of string used to describe a function, class, or module.
It works like a comment, but it can also be accessed at runtime using special functions like help() or .__doc__.
Example:
def greet(name): 
"""This function greets the person with the provided name.""" 
print("Hello,", name) 
# Accessing docstring 
print(greet.__doc__) 
greet("Jani")
output:
This function greets the person with the provided name. 
Hello, Jani 
What is super() in Python?
super() is a built-in function used to call the parent class’s methods or constructor inside the child class.

 Use Cases of super():
To reuse parent class constructor.
To call parent class method from child class.
To avoid rewriting same initialization logic

 Practice Examples on super()
 Example 1: Calling Parent Constructor
class Parent:
    def __init__(self):
        print("Parent constructor called")

class Child(Parent):
    def __init__(self):
        super().__init__()  # Calls Parent's constructor
        print("Child constructor called")

c = Child()
 Output:
Parent constructor called
Child constructor called
 Example 2: Calling Parent Method from Child
class Parent:
    def show(self):
        print("Parent method")

class Child(Parent):
    def show(self):
        super().show()   # Call parent method
        print("Child method")

c = Child()
c.show()
 Output:
Parent method
Child method

 Example 3: Real-life Example – Employee and Manager
class Employee:
    def __init__(self, name):
        self.name = name

    def show(self):
        print("Employee:", self.name)

class Manager(Employee):
    def __init__(self, name, department):
        super().__init__(name)
        self.department = department

    def show(self):
        super().show()
        print("Department:", self.department)

m = Manager("Jani", "IT")

 What is Hybrid Inheritance?
Hybrid Inheritance is a combination of two or more types of inheritance.
For example, combining:
Single Inheritance
Multiple Inheritance
Multilevel Inheritance
 It's used when real-world problems can't be represented using just one type of inheritance.

 Real-life Analogy:
Think of a Teacher who is:
A Person (single inheritance)
A SubjectExpert (multilevel)
And also an Employee (multiple inheritance)

 Simple Example Code: Hybrid Inheritance
# Base class
class Person:
    def display(self):
        print("I am a person.")

# Single Inheritance
class Student(Person):
    def show(self):
        print("I am a student.")

# Another base class
class Sports:
    def play(self):
        print("I play sports.")

# Multiple + multilevel inheritance
class CollegeStudent(Student, Sports):
    def college_info(self):
        print("I am a college student.")

# Creating object
cs = CollegeStudent()
cs.display()       # From Person
cs.show()          # From Student
cs.play()          # From Sports
cs.college_info()  # Own method

 Output:
I am a person.
I am a student.
I play sports.
I am a college student.

 Explanation for Students:
Person is the base class.
Student inherits from Person → Single Inheritance
Sports is a separate class.
CollegeStudent inherits from both Student and Sports → Multiple + Multilevel → Hybrid

      ↓           ↓
   Student      ←
        ↓
   CollegeStudent

I am a trainer.
I am a programmer.
